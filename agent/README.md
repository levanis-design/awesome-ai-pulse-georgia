# კოლექციის კურატორი აგენტი

ეს საქაღალდე Awesome AI Pulse Georgia-ს „კურატორს" შეიცავს — პროგრამას, რომელიც ყოველ დილით თავად ათვალიერებს სიას და GitHub-ს, ეძებს, რა შეიცვალა და რა გამოვიდა ახალი, და ცვლილებებს გთავაზობს. თვითონ არაფერს ცვლის: სია მხოლოდ შენი თანხმობის შემდეგ იცვლება. მასთან საუბარი Grok Bot-იდანაც შეიძლება.

წარმოიდგინე ბიბლიოთეკარის თანაშემწე. ყოველ დილით თაროებს ჩამოუვლის (სიაში არსებულ რეპოებს), გაზეთს გადაათვალიერებს (GitHub-ის ძიებას და Trending-ს), ყოველ მიგნებაზე ბარათს დაწერს და მაგიდაზე დაგიდებს. შენ ხელს აწერ ან უარს ეუბნები. ხელმოწერილ ბარათებს ის თავად ასრულებს, მაგრამ ჯერ კატალოგს ამოწმებს, რომ ყველაფერი ერთმანეთს ემთხვეოდეს.

## როგორ მუშაობს

**1. სკანი** — `.github/workflows/agent-scan.yml`, ყოველდღე 08:17-ზე თბილისის დროით. აგენტი სიაში არსებულ ყველა რეპოს ამოწმებს: ხომ არ წაიშალა, ხომ არ დაარქივდა, ხომ არ გადავიდა ახალ მისამართზე, ხომ არ ჩავიდა ~3,000 ვარსკვლავს ქვემოთ, ან წელზე მეტია ხომ არ განახლებულა. შემდეგ ახალ რეპოებს ეძებს. ყოველ მიგნებაზე იქმნება GitHub Issue (ჩანაწერი პროექტის „საკითხების" სიაში) ლეიბლით `agent:proposal`. ახალი რეპოს ქართულ აღწერას Claude წერს, მერე იმავე რეპოს README-სთან ადარებს და ფაქტებს ამოწმებს.

**2. დამტკიცება** — შენ. Grok Bot-ში ეუბნები „დაამტკიცე #12", ან GitHub-ზე Issue-ს ამატებ ლეიბლს `agent:approved`. უარისთვის — `agent:rejected`.

**3. შესრულება** — `.github/workflows/agent-apply.yml`. დამტკიცება ამ workflow-ს (ავტომატურ სამუშაო პროცესს GitHub-ზე) რთავს. ის README-ს ცვლის, ყველა ციფრს ასწორებს (ბეჯები, ბანერი, საიტი, MCP-ის აღწერები), MCP-ის და საიტის მონაცემებს თავიდან აწყობს და შემოწმებებს უშვებს. მხოლოდ ყველა შემოწმების გავლის შემდეგ ინახავს ცვლილებას main-ზე, ერთ commit-ად (შენახვის წერტილად), და MCP სერვერის npm-ზე გამოქვეყნებას რთავს. Issue იხურება ამ commit-ის ბმულით. თუ რამე ვერ გაიარა, არაფერი ინახება და Issue-ზე წერია, რატომ.

**4. Grok-ის კარიბჭე** — `src/gateway.ts`. პატარა სერვერი Deploy ON-ზე, რომელსაც Grok MCP-ით (Model Context Protocol — სტანდარტი, რომლითაც AI ასისტენტები გარე ხელსაწყოებს იძახებენ) ესაუბრება. ის კოლექციას კითხულობს, შეთავაზებებს გაჩვენებს და დამტკიცებისას მხოლოდ ლეიბლს ამატებს. ფაილების შეცვლა არ შეუძლია.

## რა არის დაცული

სიაში არაფერი იცვლება შენი დამტკიცების გარეშე. სრულდება მხოლოდ ის Issue, რომელიც აგენტმა (`github-actions[bot]`) ან შენ შექმენი — სხვისი ჩანაწერი, თუნდაც `agent:approved` ლეიბლით, უარყოფილია. დამტკიცებად კი ითვლება მხოლოდ ის ლეიბლი, რომელიც შენმა ანგარიშმა დაამატა: სხვა ვინმემ რომც დაამატოს, შესრულებისას უარყოფილი იქნება. Grok შენი ტოკენით მუშაობს, ამიტომ მისი დამტკიცება შენად ითვლება. აკრძალული სია (`config/rules.json` → `exclude`: sub2api, heretic, DSH-ის ეკოსისტემა, watermark-ის წამშლელები და სხვ.) არასოდეს შემოდის, არც შენი შეთავაზებით. დამატებამდე აგენტი იმ დღის ციფრებით კიდევ ერთხელ ამოწმებს, რომ რეპო არ დაარქივებულა, fork (სხვისი რეპოს ასლი) არ არის, ნაყიდი ვარსკვლავების ნიშნები არ აქვს და ზღვარს ზემოთაა. ყოველი შესრულება ერთი commit-ია, ამიტომ ერთი ბრძანებით ბრუნდება.

ერთი რამ პირდაპირ უნდა გითხრა: Grok-ს სერვერი ეუბნება, რომ დაამტკიცოს მხოლოდ შენი პირდაპირი „კი"-ს შემდეგ, მაგრამ ეს მოდელისთვის მიცემული მითითებაა და არა საკეტი. თუ Grok-ს ოდესმე რომელიმე ვებგვერდი ან შეთავაზების ტექსტი შეაცდენს, მას ერთდროულად რამდენიმე ღია შეთავაზების დამტკიცება შეუძლია. თითოეული მაინც ყველა შემოწმებას გადის და ერთი commit-ით ბრუნდება, მაგრამ სიაში მოხვდება, სანამ არ შეამჩნევ. უფრო სერიოზული შემთხვევაა, თუ კარიბჭის GitHub-ის ტოკენი (PAT) გაჟონავს: მისით სხვას შეუძლია შენი სახელით შეთავაზება შექმნას და თვითონვე დაამტკიცოს. ამიტომ ტოკენი მხოლოდ ამ ერთ რეპოზე მუშაობს, მხოლოდ ქვემოთ ჩამოთვლილი უფლებები აქვს და 90 დღეში იწურება. თუ Issues-ში ან commit-ებში უცნობ რამეს დაინახავ, ტოკენი GitHub-ზე მაშინვე გააუქმე.

## ერთჯერადი გამართვა

### 1. Claude-ის გასაღები (აღწერების დასაწერად)

1. გახსენი console.anthropic.com → API Keys → Create Key და დააკოპირე გასაღები.
2. იქვე, Billing-ში, დააწესე თვიური ხარჯის ლიმიტი — ასე ხარჯი შენს კონტროლშია.
3. GitHub-ზე: რეპო → Settings → Secrets and variables → Actions → New repository secret. სახელი: `ANTHROPIC_API_KEY`, მნიშვნელობა: გასაღები.
4. სურვილისამებრ, იმავე გვერდის Variables ჩანართში შეგიძლია დაამატო `AGENT_MODEL`, თუ სხვა მოდელი გინდა. ნაგულისხმევია `claude-sonnet-5-5`.

გასაღების გარეშეც მუშაობს: ჯანმრთელობის შემოწმება და ინგლისური აღწერების განახლება ხდება, მხოლოდ ახალი რეპოები და აღწერების გადახედვა ელოდება გასაღებს.

### 2. პირველი სკანი

GitHub → Actions → Agent scan → Run workflow. 10–20 წუთში Issues-ში შეთავაზებები გამოჩნდება.

### 3. კარიბჭე Deploy ON-ზე

**ა) GitHub-ის ტოკენი** — fine-grained PAT (პირადი წვდომის გასაღები, რომელიც მხოლოდ ამ ერთ რეპოზე მუშაობს). github.com → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token:

- Repository access: Only select repositories → `awesome-ai-pulse-georgia`
- Permissions: Actions — Read and write (სკანის გასაშვებად); Issues — Read and write (შეთავაზებებისთვის); Contents — Read-only (ფაილების წასაკითხად). Metadata ავტომატურად ემატება. სხვა არაფერი მისცე.
- Expiration: 90 დღე. ვადის გასვლისას ახალს შექმნი და Deploy ON-ში შეცვლი.

**ბ) MCP_TOKEN** — Grok-ის „პაროლი" კარიბჭისთვის, მინიმუმ 32 სიმბოლო. ტერმინალში:

```
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

**გ) სერვისი Deploy ON-ზე** — ახალი სერვისი ამ GitHub რეპოდან:

- Root directory: რეპოს ძირი (არა `agent` — კარიბჭე `mcp/src`-ის კოდსაც იყენებს)
- Dockerfile path: `agent/Dockerfile`
- Port: `8080`, health check: `/healthz`
- Secrets: `MCP_TOKEN` (ბ-დან) და `GITHUB_TOKEN` (ა-დან)

შემოწმება: ბრაუზერში გახსენი `https://<სერვისის-მისამართი>/healthz` — უნდა ჩანდეს `{"ok":true,"service":"aipulse-georgia-agent"}`.

უფასო გეგმაზე (64 MB მეხსიერება, ¼ პროცესორი) კარიბჭე გაიზომა: დატვირთვისას ~44 MB იკავებს და ერთხელაც არ გაჩერებულა.

### 4. Grok Bot-ის დაკავშირება

grok.com → Connectors → New Connector → Custom:

- URL: `https://<სერვისის-მისამართი>/mcp`
- Header: `Authorization: Bearer <MCP_TOKEN>`

შემოწმება: ჰკითხე Grok-ს „რამდენი რეპოა კოლექციაში?"

## ყოველდღიური გამოყენება

| Grok-ს ეუბნები | რას აკეთებს |
|---|---|
| „რა შეთავაზებები გაქვს?" | ღია შეთავაზებებს აჩვენებს (`list_proposals`) |
| „#12 სრულად მაჩვენე" | ერთ შეთავაზებას აჩვენებს მთლიანად (`get_proposal`) |
| „დაამტკიცე #12 და #15" | ლეიბლს ამატებს, შესრულება რამდენიმე წუთში იწყება (`approve_proposals`) |
| „#13 უარყავი, ეს არ მინდა" | ხურავს; უარყოფილ დამატებას აგენტი აღარ შემოგთავაზებს (`reject_proposals`) |
| „ეს რეპო შეაფასე: https://github.com/…" | აგენტი წესებით აფასებს და პასუხს Issue-ზე წერს (`suggest_repo`) |
| „ახლავე გაუშვი სკანი" | დღიურ სკანს ახლა რთავს (`run_scan`) |
| „ბოლო დროს რა მოხდა?" | ბოლო გაშვებებს და commit-ებს აჩვენებს (`agent_activity`) |
| „ხმის რომელი ხელსაწყოებია სიაში?" | კოლექციაში ეძებს (`search_collection`, `list_category`, `get_repo_details`) |

Grok-ის გარეშეც იგივე შეგიძლია GitHub-ზე: Issues → ფილტრი `label:agent:proposal` → დაამატე `agent:approved` ან `agent:rejected`.

## წესები ერთ ფაილში

`config/rules.json` — აგენტი მას ყოველ გაშვებაზე კითხულობს, ამიტომ რიცხვის შესაცვლელად კოდის შეხება არ გჭირდება:

| პარამეტრი | მნიშვნელობა | რას ნიშნავს |
|---|---|---|
| `minStarsNew` | 5000 | 60 დღეზე ახალ რეპოს ამდენი ვარსკვლავი სჭირდება |
| `minStarsOld` | 20000 | უფრო ძველ, ჯერ არშეტანილ რეპოს — ამდენი |
| `floorIndependent` × `floorSlack` | 3000 × 0.9 | დამოუკიდებელი პროექტის ამოღება 2,700-ზე ქვემოთ (ოფიციალური ვენდორები არ ეხება) |
| `minForkRatio`, `minCommits` | 0.01, 20 | ნაყიდი ვარსკვლავების ნიშნები |
| `staleMonths` | 12 | ამდენი თვე განახლების გარეშე — თარიღიანი შენიშვნა |
| `maxNewPerScan`, `maxDescriptionReviewsPerScan` | 8, 5 | Claude-ის დღიური ბიუჯეტი |

იქვეა ოფიციალური ვენდორების სია (`vendorOwners`) და აკრძალული რეპოები (`exclude`).

## ხარჯი

GitHub Actions საჯარო რეპოსთვის უფასოა. Claude-ს დღეში მაქსიმუმ ~30 მოთხოვნა მიდის (8 ახალი რეპო, თითოზე აღწერა და ფაქტების შემოწმება, პლუს 5 გადახედვა), უმეტეს დღეს ბევრად ნაკლები: AI-სთან კავშირის გარეშე რეპოები მოდელამდე არ მიდის, ხოლო ერთხელ უარყოფილს აგენტი 30 დღე იმახსოვრებს. ზუსტი ფასი მოდელზეა დამოკიდებული — ამიტომაა საჭირო ლიმიტი Anthropic Console-ში. Deploy ON-ის უფასო გეგმა საკმარისია.

## როცა რამე არ მუშაობს

- Issue-ს `agent:failed` ლეიბლი აქვს — კომენტარში წერია მიზეზი. გამოსწორების შემდეგ თავიდან დაამტკიცე.
- სკანის გაშვება წითელია — Actions → Agent scan → ეს გაშვება: შეჯამებაში ჩანს, რომელმა წყარომ ვერ იმუშავა.

## დეველოპერისთვის

```
cd agent
npm ci
npm test                                       # ყველა ტესტი, ქსელის გარეშე
npm run verify                                 # README, ციფრები და მონაცემები ემთხვევა?
GITHUB_TOKEN=<token> npm run scan -- --dry-run # ნამდვილი სკანი, GitHub-ზე ჩაწერის გარეშე
```

ბრძანებების პარამეტრები:

| პარამეტრი | სად | რას აკეთებს |
|---|---|---|
| `--dry-run` | scan, suggest, apply, report | არაფერს წერს არც GitHub-ზე, არც ფაილებში |
| `--no-discover` | scan | მხოლოდ სიაში არსებული რეპოების შემოწმება, ახლების ძიების გარეშე |
| `--max-new N` | scan | დღეს მაქსიმუმ N ახალი რეპო გადაეცეს Claude-ს |
| `--memory FILE`, `--out FILE` | scan | მოდელის ძველი გადაწყვეტილებების ფაილი; სრული ანგარიში JSON-ად |
| `--issue N` | suggest | რომელ შეთავაზებას უპასუხოს |
| `--issues 12,15` | apply | მხოლოდ ეს დამტკიცებული Issue-ები |

გარემოს ცვლადები (environment variables — პროგრამის გარედან მიწოდებული პარამეტრები): `GITHUB_TOKEN`, `ANTHROPIC_API_KEY`, `AGENT_MODEL` (ნაგულისხმევი `claude-sonnet-5-5`), `AGENT_LOG_LEVEL=warn` (ნაკლები ჩანაწერი ლოგში); კარიბჭისთვის დამატებით `MCP_TOKEN`, `AGENT_REPO`, `AGENT_BRANCH` (ნაგულისხმევი `main`) და `PORT` (ნაგულისხმევი `8080`).
